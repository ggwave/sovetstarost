# Совет обучающихся — сайт и CRM

Firebase project ID: **`sovet-701c5`**. Это статический сайт с публичной главной страницей и закрытой CRM для Совета обучающихся. Архив содержит исходники сайта и правила Cloud Firestore; он не публикует изменения в Firebase Console или GitHub Pages автоматически.

## Технологии и вход

- Firebase JavaScript SDK **13.4.0**, compat build.
- Firebase Authentication: вход **Email/Password**.
- Cloud Firestore: данные Совета, профили, инициативы, задачи, события и отчёты.
- Регистрации на сайте нет. Председатель сначала создаёт Auth-пользователя через Firebase Console, затем добавляет его профиль в CRM.
- Пароли хранятся только в Firebase Authentication. Пароль не записывается в Firestore.
- При входе проверяется активный документ `users/{uid}`. Без него доступ к CRM запрещён.

## Устройство Совета

Система отражает проект «Сектора»: административный сектор и пять рабочих направлений — информационный, культурно-массовый, социальный, учебно-проектный и спортивный. Председатель, заместители и секретарь автоматически относятся к административному сектору. Административный сектор координирует работу остальных направлений.

### Роли

| `role` | Отображаемая роль | Сектор |
|---|---|---|
| `chair` | Председатель Совета | `administrative` автоматически |
| `deputy_chair` | Заместитель председателя | `administrative` автоматически |
| `secretary` | Секретарь Совета | `administrative` автоматически |
| `administrative` | Участник административного сектора | `administrative` автоматически |
| `sector_lead` | Руководитель сектора | Один из пяти рабочих секторов |
| `member` | Участник Совета | Один из пяти рабочих секторов либо без назначения |

Только председатель управляет списком участников, ролями, секторами, включением/отключением доступа и публикацией участников на главной. Включайте публичное отображение имени и роли только с согласия самого участника. Основной аккаунт председателя нельзя изменить или отключить через список участников. Участники административного сектора могут координировать общие разделы и планы всех секторов, но не могут выдавать роли.

## Реализованные CRM-модули

1. **Обзор** — количество задач, открытых голосований, ближайшие собрания и быстрые переходы.
2. **Инициативы** — входящие обращения, ID, статус, назначение сектора, копирование публичной ссылки отслеживания.
3. **Мой сектор** — обязанности, состав команды и план своего направления.
4. **Участники** — создание Firestore-профилей для заранее созданных Auth-пользователей, редактирование роли/сектора и отключение доступа (председатель).
5. **Управление секторами** — состав, руководители, цели и планы шести секторов; планы может координировать административный сектор.
6. **Собрания** — создание, изменение повестки/даты/времени/места, публикация на главной, изменение статуса, удаление.
7. **Голосования** — опрос с одним или несколькими вариантами, дедлайн, публикация, голос участника, результаты, закрытие и удаление.
8. **Задачи** — создание поручений, назначение ответственных, сроки, приоритеты, статусы, редактирование и удаление; исполнитель может менять статус своей задачи.
9. **Решения** — фиксация решений Совета, связь с собранием, ответственный сектор и статус исполнения.
10. **Объявления** — публикация новостей и объявлений; информационный сектор работает со своим направлением, административный — со всеми.
11. **Документы и материалы** — запись текстов и ссылок, категории, описания, публикация/снятие с публикации.
12. **Отчёты секторов** — ежемесячная отчётность руководителей, принятие административным сектором или возврат на доработку с комментарием.
13. **Аналитика** — сводные показатели инициатив, задач, проектов, голосов, собраний и отчётов.
14. **Архив** — автоматически собранный список завершённых/отменённых объектов.
15. **Мой профиль** — имя и контактные данные; роль и сектор отображаются для чтения.
16. **Настройки** — смена пароля через повторную проверку Firebase Authentication.

## Публичная часть

- Главная страница, описание и структура Совета, обязанности секторов.
- Новости, опубликованные объявления, собрания, проекты, планы секторов, состав команды (только отмеченные председателем профили) и документы/материалы подгружаются из Firestore.
- Любой учащийся может отправить инициативу без входа.
- После отправки генерируется ID формата `IN-YYYYMMDD-XXXXXXXX` и персональная ссылка `?tracking=ID#track`.
- Публичная карточка статуса показывает ID, название, сектор и статус/даты. Имя, класс и контакты автора в публичную карточку не включаются.
- Участник Совета, войдя в CRM, может перейти на обычную публичную главную через кнопку **«Главная сайта»**; с неё доступен обратный переход **«В рабочую CRM»**.

## Внутрисайтовые уведомления

CRM в реальном времени слушает коллекцию `activityFeed`. Всплывающие уведомления и список событий появляются при новых инициативах, собраниях и голосованиях, пока пользователь авторизован и держит сайт открытым.

Это **внутрисайтовые уведомления**, а не push: они не приходят, когда браузер/сайт закрыт. Firebase Cloud Messaging и браузерные разрешения в этой версии не настраивались. Старые события не показываются как новые при первом входе/подключении слушателя.

## Данные Firestore

| Коллекция / путь | Назначение |
|---|---|
| `users/{uid}` | Профили, роли, сектор, active |
| `initiatives/{trackingId}` | Полная инициатива, включая закрытые контактные поля |
| `initiativeTracking/{trackingId}` | Безопасная публичная карточка статуса, доступна по точному ID |
| `activityFeed/{eventId}` | События для списка и всплывающих уведомлений |
| `meetings/{meetingId}` | Собрания и повестки |
| `polls/{pollId}` | Голосования и варианты |
| `polls/{pollId}/votes/{uid}` | Один голос на Auth UID |
| `tasks/{taskId}` | Поручения |
| `decisions/{decisionId}` | Решения Совета |
| `announcements/{announcementId}` | Объявления |
| `documents/{documentId}` | Текстовые материалы и URL |
| `projects/{projectId}` | Проекты |
| `sectorPlans/{sectorId}` | Планы секторов, в том числе публикуемые на главной |
| `publicTeam/{uid}` | Отдельная безопасная публичная карточка участника без почты и контактов |
| `sectorReports/{reportId}` | Отчётность секторов |

`firestore.rules` содержит проверку ролей, валидацию полей, точечное публичное чтение карточки отслеживания и запрет всех неописанных путей. Публичный пользователь может создавать инициативу, но не читать коллекцию полных обращений.

## Важные ограничения версии

- **Голосования не анонимные.** Голос хранится под UID участника; текущая реализация показывает состав голосов и результаты участникам CRM. Не используйте её для тайного/персонально-конфиденциального голосования.
- **Файлы не загружаются в Storage.** В модуле документов хранятся текст и внешняя ссылка. Для вложений с компьютера потребуется Firebase Storage и отдельные Storage Rules.
- **У публичной формы нет App Check / CAPTCHA и серверного ограничения частоты.** Правила Firestore ограничивают структуру записей, но это не полноценная защита от массового спама.
- Публичная карточка статуса доступна любому, кто знает ID. Не добавляйте туда персональные сведения.
- Результаты ниже 100% готовности не заявляются: перед рабочим использованием нужно выполнить настройки Firebase, создать первый профиль председателя и проверить реальные сценарии с тестовыми аккаунтами разных ролей.
- Чат, Telegram, SMS, сторонние базы и внешние серверы отсутствуют.

## Первый запуск Firebase

1. В Firebase Console открой проект `sovet-701c5`.
2. Authentication → Sign-in method → включи **Email/Password**.
3. Authentication → Users → Add user: создай первый аккаунт председателя и сохрани UID.
4. Создай Cloud Firestore (Production mode) при необходимости.
5. Firestore → Data → создай коллекцию `users`; ID документа — UID председателя. Поля: `name` (string), `email` (string), `role` (string=`chair`), `sectorId` (string=`administrative`), `active` (boolean=`true`), `createdAt` (timestamp).
6. Firestore → Rules → вставь `firestore.rules` из архива → Publish.
7. В Authentication → Settings → Authorized domains добавь домен публикации сайта и `localhost` для локального теста.
8. Открой сайт, войди как председатель, создай Auth-аккаунт ученика через Console и добавь его профиль в CRM → Участники.

`js/firebase-config.js` уже нацелен на Firebase project `sovet-701c5`. Конфигурация веб-приложения не является секретом; не добавляй в клиент приватные service-account ключи.

## Локальный запуск

1. Распакуй ZIP.
2. Открой PowerShell в каталоге проекта.
3. Выполни `py -m http.server 8080`.
4. Открой `http://localhost:8080`.
5. Для входа Firebase должен разрешать домен `localhost`.

Для публикации на GitHub Pages загрузи содержимое папки проекта в репозиторий, сохранив структуру файлов. Правила Firestore публикуются отдельно через Firebase Console.
