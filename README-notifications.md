# Уведомления Firebase для «Совета старост»

В комплекте:
- `sovet-starost-notifications.html` — сайт с персональными настройками уведомлений и кнопкой включения push;
- `firebase-messaging-sw.js` — обработчик фоновых web push;
- `functions/index.js` — серверные Firebase Cloud Functions для push по событиям и напоминаний;
- `firebase.json`, `functions/package.json`;
- `firestore.rules` — безопасная отправная точка для будущей миграции на Firebase Authentication.

## ВАЖНО ПРО АВТОРИЗАЦИЮ И БЕЗОПАСНОСТЬ

Текущая версия сайта использует самодельный вход по полям `login/password` из коллекции `users`, а не Firebase Authentication. Поэтому сервер не может надёжно доказать, кто именно совершил действие, и безопасные правила Firestore с `request.auth` сразу заблокируют существующий сайт. Кроме того, старый код хранит пароль в документах Firestore. Это архитектурная проблема, а не то, что можно исправить одной Cloud Function.

**Не публикуйте текущую базу с широкими правилами.** Для полноценной безопасной эксплуатации нужно мигрировать вход на Firebase Authentication, связать профиль с Firebase UID, перенести пароли в Auth и затем адаптировать правила для всех существующих коллекций. Файл `firestore.rules` намеренно является deny-by-default шаблоном и НЕ должен развёртываться до миграции: он блокирует старый сайт.

## 1. Установить Firebase CLI

```bash
npm install -g firebase-tools
firebase login
firebase use sovet-701c5
```

Откройте папку проекта (где лежит `firebase.json`) и установите зависимости:

```bash
cd functions
npm install
cd ..
```

Cloud Functions и Scheduler могут потребовать подключить биллинг-план Blaze в Firebase/Google Cloud. Учитывайте возможные расходы и квоты перед включением.

## 2. Настроить Web Push

1. Firebase Console → Project settings → Cloud Messaging → Web Push certificates.
2. Создайте/скопируйте **публичный VAPID key**.
3. В `sovet-starost-notifications.html` замените `PASTE_PUBLIC_VAPID_KEY_FROM_FIREBASE_CONSOLE` в `FCM_VAPID_KEY`.
4. Разместите HTML и `firebase-messaging-sw.js` на одном HTTPS-домене. `file://` не поддерживается; `localhost` годится для локального теста.
5. После входа откройте «Уведомления» и нажмите «Включить push в браузере».

Публичный VAPID-ключ не является секретом. Секретные ключи Admin SDK/FCM нельзя помещать в HTML, репозиторий или ZIP.

## 3. Развернуть серверные функции

После настройки Authentication и правил Firestore:

```bash
firebase deploy --only functions
```

`firebase deploy --only firestore:rules` запускайте только после полной адаптации правил и миграции авторизации. Текущий `firestore.rules` безопасно закрывает доступ по умолчанию, но старый HTML на нём работать не будет.

## 4. События

- новое голосование (`polls/{id}`);
- назначено собрание (`meetings/{id}`);
- новое сообщение в чате (`chatMessages/{id}`), без push автору сообщения;
- новое/одобренное объявление (`announcements/{id}`);
- опубликованное решение (`decisions/{id}`);
- напоминание за 30 минут до собрания/события, планировщик проверяет раз в 5 минут, часовой пояс `Europe/Moscow`.

Настройки каждого пользователя сохраняются в поле `users/{uid}.notificationPrefs`. Токены устройства — в `users/{uid}.fcmTokens`. Cloud Functions создаёт записи истории уведомлений и отправляет push серверной Admin SDK, не раскрывая серверные ключи в браузере. Функции используют Admin SDK, который обходит Firestore Rules; доступ к изменению функций и IAM нужно ограничить администраторам проекта.

## 5. Проверка

1. Проверьте функции в Firebase Console → Functions → Logs.
2. Убедитесь, что VAPID-ключ задан, сайт открыт через HTTPS и пользователь дал разрешение браузеру.
3. Создайте тестовое голосование, собрание, одобренное объявление и сообщение в чате.
4. Проверьте напоминание на тестовом событии в пределах следующих 30 минут.

Поскольку у проекта есть старые коллекции и кастомная авторизация, это комплект для интеграции и развёртывания, но подключение реального проекта из этой среды не выполнялось. Перед боевым использованием обязательно мигрируйте авторизацию и протестируйте правила на тестовом проекте.
